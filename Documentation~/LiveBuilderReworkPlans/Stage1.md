# План этапа 1 «Скорость» Live Builder (архитектор)

Код не писал, Unity не запускал. Всё ниже взято из чтения кода. Числа в разделе «Бюджеты» — оценки, мерить их будем на шаге 3.

## 1. Что делаем и зачем

Пока человек тянет ручку, модуль на каждом шаге заново собирает **весь** объект целиком: с фаской, коллайдером и записью файла. Делаем так:
- во время жеста идёт черновая сборка, только того, что правка задела;
- чистовая (фаска, коллайдер, подпись) — через 0,3 с после отпускания;
- запись на диск — после 2 с тишины или при сохранении сцены.

Пример. На 300-коробочной ограде тянешь колонну на клетку. Сейчас на каждом шаге заново решается весь объект и вся фаска, а это секунды. После правки пересчитаются только колонна и 3–5 соседних коробок, без фаски. Фаска появится через 0,3 с после отпускания.

## 2. Как устроено сейчас (по коду)

**Путь пересборки.** Её запускают события Unity:
- `ObjectChangeEvents`, Undo, `Spline.Changed`, открытие сцены (`LiveBuilderRebuildQueue.cs:28-39`);
- прямые вызовы `Rebuild` в конце рисования: `BoxModelDrawGesture.cs:286,311,313`, `LiveBuilderOpeningPlacer.cs:356-372`, `LiveBuilderRoomGesture.cs:106,193`, `LiveBuilderStairsGesture.cs:266,270`, `LiveBuilderSurfaceBoxGesture.cs:143`.

Ручки граней, переноса и проёма меш сами не трогают. Они меняют данные с Undo (`BoxModelPartHandles.cs:200`, `GeometryCutterHandles.cs:113,144`, `LiveBuilderMoveHandle.cs:215`), а пересобирает очередь.

```
СЕЙЧАС
правка → RequestCheck: ждёт 0,05 с тишины, каждая правка сдвигает срок (:44-51)
→ один проход по ВСЕЙ сцене (:56-78):
   LinkSync.SyncAll → Anchors.SyncAll → LineSync.SyncAll → забыть расчёт ВСЕХ объектов
   → каждый BoxModel: Tidy, Collect + подпись;
     подпись другая → Solve(весь список) → Surfaces → Fill → Bevel → Chamfer
       → Cutters (BSP) → коллайдер → RequestSave через 0,5 с
   → каждое здание: подпись; не сходится → BuildParts ВСЕХ частей
       → пишет части с другой подписью → Cutters → коллайдер
   → каждая стена — так же
UV2 (развёртка под запекание) — только при сохранении сцены/префаба и перед запеканием
```

Где стадии в коде:
- солвер — `BoxModelSolver.cs:78-134`, вызов из `BoxModelRebuilder.cs:272`;
- поверхности — `BoxModelSurfaceFinder.cs:33-65`;
- заливка меша, фаска, скосы — `BoxModelRebuilder.cs:201-207`;
- проёмы — `GeometryCutterApplier.cs:28-34` через `MeshSubtraction.SubtractNear`;
- запись меша — `LiveBuilderMeshWriter.cs:62-92`;
- коллайдер — `LiveBuilderMeshWriter.cs:165-185`;
- диск — `BoxModelMeshStorage.cs:25,151-170`;
- UV2 — `BoxModelMeshStorage.cs:215-223` и `BoxModelMeshSaving.cs:22-24,33,111`.

**Во время жеста сейчас:**
- Пересборка полная, с фаской (`BoxModelRebuilder.cs:204`) и запеканием коллайдера (`:161`).
- Развёртка UV2 во время жеста **не считается** — это требование уже выполнено.
- Запись на диск — через 0,5 с после последней правки, и она не выключена на время жеста. Задержал мышь на полсекунды — файл пишется.
- Очередь работает как «ждать тишины» (`:50`): при быстрых кадрах проход откладывается, пока мышь не замрёт на 50 мс. Меш отстаёт от ручки.
- Фаска — главный тормоз. Рёбра ищутся перебором «каждая поверхность с каждой» (`BoxModelBevel.cs:118-165`). На каждое ребро `SubtractNear` заново пересчитывает габарит всех многоугольников и пересобирает весь список (`MeshSubtraction.cs:31-47,87-95`). На сотнях коробок это скорее всего секунды; документ так и пишет — «заметно».

**Солвер.** Идёт по коробкам по очереди: каждая следующая режет всё набранное (`BoxModelSolver.cs:82-98`). Из этого следует:
- куски коробки i зависят только от неё и упорядоченного списка более поздних коробок, которые её пересекают;
- куски каждой коробки лежат в итоговом списке подряд, в порядке коробок.

Значит, кеш по коробкам делается **без переписывания алгоритма**. Ключ коробки — она сама плюс её «резчики». Номера коробок-источников граней храним относительные: 0 — сама коробка, k — k-й резчик. При сборке подставляем глобальные номера. Результат совпадает с нынешним байт в байт, включая порядок.

Сейчас при любой правке сцены все объекты заново собирают коробки и подпись (`BoxModelRebuilder.cs:250-278`). Если подпись другая — солвер решает весь список заново.

Этап 2 меняет только правило «кто режет коробку i»: все пересекающие её вырезы плюс более поздние добавляющие. Ключ и кеш от этого не ломаются.

**Здание.** «Пересобирается только затронутый этаж» — правда только для проёма на одном этаже (есть тест `LiveBuilderRebuildTests.cs:47-63`). В остальных случаях — нет:
- В подписи здания число этажей и все вырезающие коробки (`SplineBuildingRebuilder.cs:209,231-235`). 9→10 этажей или правка лестницы с вырезом над ней пересобирают все части.
- В ключе проёма есть число копий `CopiesUp` (`GeometryCutterLookup.cs:269`). При новом этаже меняются ключи всех этажей, которые режет окно «на всех этажах».
- `Rebuild` всегда строит геометрию **всех** частей (`SplineBuildingRebuilder.cs:88-90`), даже если поменялся только проём. Пропускается только запись.

**Клавиша B и выделение.** По коду пересборку не зовут:
- `LiveBuilderSceneTool.cs:54-81` — только подписки и отмена начатого;
- `LiveBuilderWindow.cs:436` — перерисовка окна;
- `ArrayModifierWatcher` на выделение подменяет копии, `PreviewCopiesChanged` не шлёт.

Подтвердим тестом со счётчиком проходов (шаг 8).

**Эталонная сцена.** Существующих API хватает, чтобы собрать её кодом:
- `BoxModelFactory`: `CreateModel/Group/Part/Room/Stairs/Wall/Building/Cutter`;
- `SplineBuildingLinkSync.Attach` — привязка «И этажи выше»;

## 3. Схема «после»

```
правка → Queue записывает «что задето» (LiveBuilderRebuildScope)
 идёт жест (LiveBuilderGestureTracker):
   каждый кадр ЧЕРНОВОЙ проход, только в границах задетого:
   сверки → BoxModel: SolverCache (только изменившиеся коробки) → Surfaces → Fill → Chamfer
          → Cutters (у проёма из жеста — заготовка без него, минус он один)
   без фаски, без коллайдера, без записи на диск → постройка в LiveBuilderDraftBuilds
 жест кончился + 0,3 с тишины → ЧИСТОВОЙ проход по всей сцене (как сейчас):
   доводит черновики (фаска, коллайдер, подпись) и ловит то, что черновой проход мог упустить
 2 с тишины и жеста нет → запись файлов
 Ctrl+S / Play / запекание / сборка игры → сначала доводка
 здание: подпись части = общее у здания + своё (этаж, верхний ли, дыры и копии проёмов в её высоте);
         геометрия строится только у частей с другой подписью
```

## 5. Что ломается и рискованно; что не трогаем

**Ломается и рискованно:**
- **Старые сцены пересоберутся один раз.** Причина — `LayoutVersion` и новый ключ проёмов. Меши выйдут те же, но подписи частей в сценах игры поменяются: сцены станут «изменёнными» при первом открытии.
- **Черновик может уйти наружу.** Поэтому доводка стоит на Play, Ctrl+S, запекании и сборке. Путь, который пропустим (чужой инструмент сам сохраняет ассеты), получит меш без фаски. Чистовой проход через 0,3 с это исправит.
- **`hotControl` может оказаться не общим** для всех окон — проверяем в начале шага 4. Запасной вариант уже заложен: доводка по таймеру «0,3 с без правок».
- **Черновой проход может упустить зависимость.** Тогда превью отстанет до доводки. После жеста ошибок не остаётся: чистовой проход проверяет всю сцену.
- **Экземпляр префаба или Shift-копия в жесте** заводит свой файл меша один раз, на первом шаге. Это отступление от «не пишется на диск»: пустой ассет, содержимое пишется позже.
- **Тесты, которые бьют лучом сразу после жеста,** держатся на доводке в `LiveBuilderToolDriver`. Тесты с прямым `Rebuild` не меняются: по умолчанию Final.
- **Помощь для MCP:** `run_tests` сохраняет открытые изменённые сцены — перед запуском проверить.

**Не трогаем:**
- компоненты данных: новых `[SerializeField]` нет, значения на префабах не обнулятся;
- интерфейс, инструменты, Undo;
- алгоритмы `MeshBoolean` и поверхностей;
- логику сверки привязок (этап 2 её заменит иерархией) — ей только область;
- предел 5000 коробок;
- конвейер «меш → многоугольники» без промежуточного `Mesh`.

## 6. Где ТЗ расходится с кодом и где бюджет под угрозой

**Расхождения:**
1. Требование 4 «как сейчас» неверно в трёх случаях: число этажей, вырезающие коробки, `CopiesUp`. Плюс геометрия всех частей строится всегда (раздел 2).
2. UV2 во время жеста уже не считается — там делать нечего.
3. Запись на диск: 0,5 с, и во время жеста не выключена.
4. Коллайдер в списке стадий ТЗ нет, а запекание коллайдера идёт на каждом шаге. Откладываем его вместе с фаской.
5. «Ускорить фаску (этап 1)» есть только в тексте этапа 6, требования и бюджета нет. Ставим свою цель ≤ 150 мс: иначе через 0,3 с после каждого отпускания редактор будет замирать.
6. ТЗ: «пересчитываются только коробки, чьи габариты пересекаются». У нас ключ по содержимому: при сдвиге это то же самое, но заодно ловятся вставка, удаление и перестановка.
7. Очередь ждёт 50 мс тишины, поэтому меш отстаёт от ручки (вывод по коду). Это одна из причин «медленно», в ТЗ не названа.

**Бюджеты, оценка «до → после».** Не замерено, уверенность средняя:

| Действие | Сейчас | После | Бюджет |
|---|---|---|---|
| сдвиг коробки в объекте на 300 коробок | ~0,5–3 с (фаска) | ~8–15 мс черновик; доводка ~100–200 мс | 30 мс — ✓ |
| сдвиг окна (копии на 9 этажах) | ~60–120 мс (все части, пересчёт всех проёмов) | ~5–10 мс (заготовка + один проём) | 16 мс — ✓, впритык без шага 7 |
| этажей 9 → 10 | ~200–500 мс | ~60–120 мс (4 части здания, объект-хозяин, шахта, коллайдеры) | 150 мс — вероятно ✓, есть риск |
| ≥ 30 кадров/с при любом жесте | — | ✓ для коробок, проёмов, рисования | — |

Под вопросом — правка контура 9-этажного здания: меняются все этажи. Решение заранее: если черновик контура дольше 33 мс, в черновике у этой постройки не режем проёмы, они вернутся при доводке. Если и так не хватит — честно отчитываемся.

Ещё два честных пункта:
- Черновой меш проёма по треугольникам отличается от чистового (форма та же) до доводки.
- Через 0,3 с после отпускания на фасочном объекте будет заметная пауза — время доводки фаски.

## 7. Решения вместо вопросов (автор дал свободу)

1. **Эталонная сцена — кодом, без `.unity`.** Повторяется, читается в diff, не тянет в пакет ~40 файлов мешей. В конце этапа сохраняем копию сцены без мешей как образец для миграции этапа 2.
2. **«Один в один» — точный отпечаток**, с порядком вершин. Кеш по построению сохраняет порядок. Отпечаток по форме — для этапов 2–6.
3. **Коллайдер — в доводку.** Невидим во время жеста, а запекание дорогое.
4. **Свой файл меша в жесте — разрешён один раз.** Превью важнее, а смысл требования — не писать на каждом шаге.
5. **Правило вырезов этапа 2 делаем сейчас, но не включаем.** Это одна функция «кто режет»; конечное устройство уже заложено.
6. **Поверхности по частям — только если больше 8 мс.** Простое решение, пока замер не скажет иначе.
7. **Ускорение фаски — в этом этапе**, с тем же результатом. Иначе пауза после каждого отпускания.
8. **Черновой проход — только по задетому.** Полный проход растёт с размером уровня; надёжность держит чистовой проход после жеста.
9. **Одноразовую пересборку старых сцен принимаем.** Меши те же; меняются только подписи в сценах.

## 8. Как проверить

**Тесты EditMode:**
- весь набор Live Builder зелёный;
- новые:
  - `LiveBuilderReferenceLevelTests` — состав уровня, точный эталон;
  - `BoxModelSolverCacheTests`:
    - случайные наборы коробок и правок (сдвиг, размер, вставка, удаление, порядок, режим) с фиксированным seed — совпадение с `Solve` до байта;
    - сдвиг одной из 300 пересчитывает только пересекающие;
    - `CutsAfterAllAdds` не зависит от порядка;
  - `LiveBuilderDraftBuildTests`:
    - во время жеста нет фаски и нет записи на диск;
    - после `FinishAll` есть фаска и коллайдер;
    - запись через 2 с;
    - Ctrl+S и Play доводят;
  - дополнения в `LiveBuilderRebuildTests`:
    - 9→10 пересобирает только стены 9-го и 10-го этажей, пол 10-го и крышу;
    - вырез над лестницей — только плиты, которые задевает;
    - окно «на всех этажах» — только его стены;
    - после жеста с проёмом меш равен эталону;
  - `ToolActivationAndSelection_RebuildNothing`.

**Замер:** `Measure Rebuild` до и после — таблица по стадиям и 4 бюджета (медиана из 20) в отчёт.

**Руками (автор):** `Open Reference Level`.
- Потянуть колонну, окно, контур, поменять число этажей.
- Смотреть кадры в Stats.
- Фаска появляется примерно через 0,3 с после отпускания.
- Счётчик записей не растёт, пока тянешь.

## 9. Суть простыми словами

- Сейчас на каждое движение мыши Live Builder заново собирает весь объект — со скруглёнными рёбрами, физикой и записью на диск. Поэтому он тормозит.
- Будет так: пока тянешь, он быстро собирает черновик только того, что трогаешь, без скруглений. Через долю секунды после отпускания всё доделывает начисто.
- Объект из коробок будет помнить каждую коробку: сдвинул одну — пересчитываются она и пара соседей, а не все 300.
- Здание при добавлении этажа будет пересобирать только верх, а не все этажи.
- Файлы пишутся, когда ты 2 секунды ничего не делаешь или сохраняешь сцену. Перед игрой и сохранением всё доделывается само.
- Сначала соберём проверочный уровень и замерим «до». В конце — «после» и проверка, что всё выглядит в точности как раньше.
- Риск один: при перетаскивании контура большого здания плавности может не хватить. Тогда окна на время перетаскивания пропадут и вернутся после.
